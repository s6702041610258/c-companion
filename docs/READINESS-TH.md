# เกณฑ์ความพร้อม C Companion — ทบทวนสำหรับ 1.6.0

เกณฑ์นี้เป็นสิ่งที่ต้องตรวจ ไม่ใช่คำยืนยันว่ามีผลทดสอบใหม่ครบทุกกรณี ดูผลล่าสุดใน [หลักฐานรุ่น](RELEASE-GATE-TH.md)

ขอบเขต: เว็บติวภาษา C สำหรับเจ้าของและกลุ่มผู้เรียนขนาดเล็ก ไม่ใช่ SLA สำหรับคนจำนวนมากหรือระบบสอบ คะแนนความพร้อมเป็นการประเมินทางวิศวกรรม แยกจากอัตราความถูกต้องของโมเดล

## เกณฑ์ก่อนเผยแพร่

| ด้าน | หลักฐานที่ต้องมี |
|---|---|
| คำตอบ | ส่งคำถามจริง 24 กรณี ครบ 12 บท ตรวจคำตอบด้วยคนและหน้าอ้างอิง; ตัวอย่าง C 2 กรณีผ่าน syntax check |
| ความทนทาน | 20 เซสชัน HTTP แบบจำลองไม่สลับคำตอบ; timeout, cancel, provider failure และ retry; ทดสอบ Hermes จริง 6 เซสชันพร้อมกัน ตอบครบภายใน 90 วินาทีต่อคำถาม และ health p95 ต่ำกว่า 1.5 วินาที |
| ความปลอดภัย | การอ่าน/ลบ/ส่งข้อความ/ยกเลิกงาน/รายงานข้ามเซสชันต้องถูกปฏิเสธ; CSRF, XSS, input validation; dependency audit และตรวจว่า Hermes ปิดเครื่องมือกับความจำร่วม |
| ปล่อยรุ่น | CI ผ่านตรง commit, source manifest ตรง VPS, backup restore integrity/write ผ่าน, HTTPS และ monitor ผ่านหลังสลับ |
| ความเข้ากันได้ | ผู้ใช้รายงานว่าทดสอบ Windows ติดตั้งใหม่ มือถือ และหลายเบราว์เซอร์แล้วดี; แยกหลักฐานนี้จากการรัน CI และ Chromium ของผู้พัฒนา |

## สิ่งที่ตรวจพบและแก้ในรุ่น 1.2.2

- ผู้ใช้คนเดียวส่งงานค้างหลายแชทได้: จำกัดรวม 2 งานต่อเซสชัน ไม่เพิ่มโควตาคำถามรายวัน/ชั่วโมง
- งานหมดเวลาถูกบันทึกเป็นยกเลิก: แยก failed ให้ monitor ตรวจพบ
- Origin ผิดรูปทำให้ 500 และ Fetch Metadata ยังไม่ถูกตรวจ: ปฏิเสธด้วย 403
- สร้างแชท/รายงานติดกันได้ไม่จำกัด: เพิ่ม burst guard รายเซสชันและรวม คืน 429/Retry-After
- argc/argv ตอบว่าไม่มีเนื้อหา: รักษาหน้า 85–86 และอธิบายชื่อ args ที่หนังสือใช้

## การทดสอบซ้ำ

```sh
npm test
npm run evaluate
npx tsc --noEmit
npm run build
npm run test:e2e
npm audit
TUTOR_URL=https://your-test-site EVALUATION_OUTPUT=/tmp/quality.jsonl node evaluation/live.mjs --all --show-answers
TUTOR_URL=https://your-test-site EVALUATION_OUTPUT=/tmp/code.jsonl node evaluation/live.mjs --code --show-answers
TUTOR_URL=https://your-test-site EVALUATION_OUTPUT=/tmp/load.json node evaluation/load.mjs
```

การทดสอบ live ใช้บัญชี AI ของระบบและอาจมีค่าใช้จ่าย ควรรันบนเว็บทดสอบในช่วงไม่มีงานอื่น ตัวทดสอบลบเฉพาะแชทที่สร้างเอง เก็บเฉพาะคำถามสังเคราะห์และคำตอบ ไม่มี cookie/token ในรายงาน การทดสอบโหลดจำกัด 2–12 เซสชัน ไม่ใช่เครื่องมือยิงโหลดไม่จำกัด

## ข้อจำกัดที่ยังคงอยู่

- ตัวอย่างคำถามที่ผ่านยังไม่แทนทุกคำถามหรือทุกครั้งที่โมเดลตอบ ต้องเพิ่มชุดประเมินจากปัญหาจริงต่อไป
- การทดสอบ 6 เซสชันเป็นช่วงสั้น ไม่รับรอง sustained load, จำนวนผู้ใช้สูงสุด หรือ uptime ระยะยาว
- ระบบใช้ anonymous session cookie เป็นสิทธิ์เข้าถึง ไม่มีบัญชีหรือการกู้ประวัติข้ามเครื่อง ผู้ที่ได้ cookie ไปมีสิทธิ์เท่ากับเจ้าของ; ควรใช้ HTTPS และแยก browser profile บนเครื่องสาธารณะ
- ผู้โจมตีหมุน cookie ข้ามเพดานต่อเซสชันได้ คิวรวมและ write guard ช่วยจำกัดทรัพยากร แต่ไม่แทน DDoS protection หรือ authentication
- ไม่มีเครื่องมือรันโค้ด/เข้าถึงเครือข่ายผ่าน Hermes API ตาม config ที่ตรวจ ไม่อ้างว่าป้องกัน prompt injection ได้ทุกชนิด
- ไม่เปลี่ยน schema เดิมหรือ dependencies; เพิ่ม index เท่านั้น ย้อนด้วย image/config 1.2.1 และ volume เดิมได้

ผลจริง ระยะเวลาที่วัด และ revision สุดท้ายเผยแพร่ใน GitHub release หลังเกณฑ์ผ่าน ไม่ถือว่าเอกสารเกณฑ์นี้เป็นผลทดสอบโดยตัวมันเอง
