# หลักฐานและขอบเขตรุ่น C Companion 1.1.2

ชุดนี้เป็น **1.1.2** สำหรับติดตั้งและใช้งานบนเครื่องของผู้รับ โดยผู้รับตั้งค่าบัญชี AI ของตนเอง รุ่นนี้มีเว็บติว C, หนังสือและแหล่งอ้างอิง, ประวัติในเครื่อง, รายงานปัญหา, ระบบสำรองฐานข้อมูล และตัวตรวจสถานะ การมีเว็บเปิดอยู่หรือการทดสอบผ่านบางส่วนไม่รับประกันว่าคำตอบทุกข้อถูกต้อง

## สิ่งที่แก้ใน 1.1.2

- คำทักทายและคำถามว่าบอททำอะไรได้บ้างได้รับคำตอบโดยตรงพร้อมคำชวนถามเรื่องภาษา C ไม่แสดงข้อความว่าไม่พบเนื้อหา และไม่ใส่อ้างอิงหนังสือที่ไม่ได้ใช้
- คำถามภาษา C ที่มีคำทักทายอยู่ด้วยยังค้นหนังสือและตรวจแหล่งอ้างอิงตามเดิม

## สิ่งที่แก้ใน 1.1.1

- คืนโหมดสว่างให้ใช้หน้าตาเดิมของ 1.0.0 และออกแบบโหมดมืดใหม่เป็นพื้นดำ สีอำพัน และตัวอักษรที่อ่านง่าย ครอบคลุมหน้าเริ่มเรียน แชท แหล่งอ้างอิง หน้าบทเรียน และหน้ารายงานปัญหา
- โหมดมืดเลือกได้จากทุกหน้า จำค่าที่เลือกไว้ในเบราว์เซอร์ และใช้ธีมตามระบบเมื่อยังไม่เคยเลือก
- ตรวจชนิด TypeScript, build และการทำงานในเบราว์เซอร์ทั้งโหมดสว่างและมืด การสลับธีมและการจำค่าหลังรีโหลด

## หลักฐานเดิมจากรุ่น 1.0.0

- การค้นหน้าหนังสือ: `npm run evaluate` ผ่าน 18/18 กรณี ครอบคลุม 12 บท คำว่า `datatype` หลายรูปแบบ คำสะกดพอยน์เตอร์ และคำถามนอกขอบเขต
- การตอบผ่านเว็บที่เปิดใช้อยู่: คำถามตัวแทน 12 บทผ่าน 12/12 กรณี โดยมีแหล่งอ้างอิงจากบทที่คาดไว้ แชททดสอบถูกลบหลังตรวจ
- อ่านทบทวนคำตอบจริงของทั้ง 12 บทแล้ว ไม่พบคำตอบที่ผิดหลักหรืออ้างอิงคนละหัวข้อในชุดตัวแทนนี้; ผลนี้ยังไม่ครอบคลุมทุกคำถามที่ผู้ใช้อาจถาม
- โจทย์คำนวณเกรดและเลขคู่–คี่ผ่านการตอบจริง 2/2 ข้อ โค้ด C ที่ตอบผ่านการตรวจไวยากรณ์ด้วย `clang -std=c11`; ยังไม่ได้ทดสอบพฤติกรรมโค้ดทุกอินพุต
- ทดสอบโค้ด: `npm test` ผ่าน 51 รายการ รวมการแยกบทสนทนา รายงานปัญหา คิวงาน คำสะกด และการนับโทเคน
- การกู้คืน: สำเนาฐานข้อมูลล่าสุดบน VPS ผ่านการตรวจ SHA-256, SQLite integrity, จำนวนแถว และการเขียนในสำเนาชั่วคราว โดยไม่ทับฐานจริง
- ติดตั้งฐานโปรแกรม `0.3.1-rc.1` จากไฟล์แจกในโฟลเดอร์ใหม่บน macOS ARM สำเร็จด้วยบัญชี OpenAI ที่เจ้าของเลือก: Hermes, เว็บ, backup และ monitor ขึ้นครบ; ตัวเปิดตรวจโมเดลตอบได้จริง
- ตอบผ่าน Hermes ที่ติดตั้งในเครื่อง 18/18 กรณีและโจทย์เขียนโค้ด C 2/2 กรณี; โค้ดผ่านการตรวจไวยากรณ์ด้วย `clang`
- ทดสอบแผงอ้างอิงปิด เปิดกลับ และเปิดเองเมื่อมีคำตอบใหม่; รายงานปัญหาในเครื่องบันทึกได้; สำเนาฐานข้อมูลผ่าน restore-check และประวัติยังอยู่หลังรีสตาร์ตเว็บ
- หลังพบว่าตัวเปิดเดิมสร้างอิมเมจซ้ำทุกครั้ง แก้แล้วและทดสอบเปิดซ้ำโดยคอนเทนเนอร์ทั้งสี่ตัวไม่ถูกสร้างใหม่; ตัวเลือก `--rebuild` สร้างใหม่ได้ตามสั่ง
- ตรวจไฟล์แจก `0.3.1-rc.2` ด้วย SHA-256 และแตกในโฟลเดอร์ใหม่: ติดตั้ง dependencies, ทดสอบ 51 รายการ, ประเมิน 18 กรณี และ build ผ่านทั้งหมด; ไฟล์แจกไม่มีค่าตั้งค่าหรือข้อมูลส่วนตัวของเครื่องทดสอบ
- จำลองอัปเกรดจาก `0.3.1-rc.1` ไป `0.3.1-rc.2` บน Mac เครื่องนี้แล้ว: เว็บและ Hermes กลับมาพร้อมใช้งาน ข้อมูลการใช้งานเดิมยังอยู่ เปิดซ้ำด้วย `Start.command` ผ่านและไม่สร้างคอนเทนเนอร์ใหม่
- รุ่น `0.3.1-rc.3` แก้การค้นตัวอย่างอาร์เรย์หน้า 51 และตารางชนิดข้อมูลหน้า 15 ในโหมดทุกบท รวมทั้งหยุดตีความ “หนังสือเขียนว่า” เป็นโจทย์เขียนโปรแกรม; เพิ่มการลองอีกหนึ่งครั้งเฉพาะเมื่อโมเดลส่งรูปแบบคำตอบหรือเลขหน้าไม่ผ่านการตรวจ
- หลังแก้: `npm test` ผ่าน 57/57, `npm run evaluate` ผ่าน 24/24, การถามจริงผ่าน Hermes 24/24 และโจทย์เขียนโค้ด 2/2 ซึ่งโค้ดผ่าน `clang -std=c11 -fsyntax-only`; คำถาม `%9s` ที่เคยเกิด HTTP 502 ตอบสำเร็จ 10/10 ครั้งติดต่อกันโดยไม่สร้างอ้างอิงจากหนังสือ และลบแชททดสอบแล้ว
- อัปเดตชุดติดตั้งบน Mac จาก `rc.2` เป็น `rc.3` โดยรักษาค่าบัญชีและ Docker volumes เดิม; ทั้งสี่บริการกลับมาพร้อมใช้งานและ Hermes ตอบการตรวจเชื่อมต่อผ่าน

## หลักฐานเพิ่มเติมจากรุ่น 1.0.0

- ผู้รับติดตั้งบน Windows และรายงานว่า Hermes ตอบคำถามได้ถูกต้องในทุกบทที่ลองทดสอบ นี่เป็นผลใช้งานจริงที่ผู้รับแจ้ง ไม่ใช่ผลตรวจอัตโนมัติหรือหลักฐานว่าคำตอบทุกแบบถูกต้อง
- ชุดซอร์ส 1.0.0 ผ่าน `npm test` 58/58, ตรวจชนิด TypeScript, `npm run evaluate` 24/24, build และการทดสอบเว็บในเบราว์เซอร์ 5/5 กรณีก่อนส่งขึ้น GitHub
- หลักฐานการทดสอบ Mac และการกู้สำเนาฐานข้อมูลด้านบนมาจากรุ่นก่อนหน้าในสายเดียวกัน การเปลี่ยนจาก rc.3 เป็น 1.0.0 ต้องผ่าน CI ของ commit รุ่น 1.0.0 อีกครั้ง

## ขอบเขตและงานติดตาม

1. รองรับการติดตั้งที่ตรวจจริงบน macOS และ Windows ขั้นตอน Linux มีให้ใช้ แต่ยังไม่มีหลักฐานติดตั้งครบกระบวนการบนเครื่อง Linux แยกจาก VPS
2. สำหรับเว็บสาธารณะ เจ้าของโครงการเลือกไม่เพิ่มโควตารายชั่วโมง/วันในแอป ผู้ติดตั้งต้องตรวจขอบเขตการใช้ AI และยอดใช้จริงกับผู้ให้บริการของตนเองก่อนเปิดให้คนอื่นใช้
3. สำเนาฐานข้อมูลใน Docker volume บนเครื่องเดียวไม่ป้องกันเครื่องเสียหรือถูกลบทั้งเครื่อง ควรเก็บสำเนานอกเครื่องและทดลองย้อนรุ่นกับข้อมูลจริงก่อนขยายผู้ใช้
4. GitHub release และ VPS เป็นการปล่อยคนละขั้น ต้องตรวจเวอร์ชันและสุขภาพของบริการบน VPS หลัง deploy จริงก่อนสรุปว่าใช้รุ่นเดียวกัน

## ขอบเขตการใช้ AI ปัจจุบัน

ข้อความผู้ใช้ไม่เกิน 3,000 ตัวอักษร, ส่งประวัติล่าสุดไม่เกิน 8 ข้อความ, คำตอบสูงสุด 1,800 โทเคนต่อการตอบ, ประมวลผลพร้อมกัน 2 คำขอ, คิวรอ 100 คำขอ และยกเลิกคำขอที่นานเกินประมาณ 100 วินาที งานเขียนโปรแกรมอาจเรียกโมเดลเพิ่มอีกหนึ่งครั้งเพื่อเลือกแนวคิดก่อนตอบ ตัวเลขเหล่านี้จำกัดทรัพยากรต่อคำขอและพร้อมกัน **ไม่ได้จำกัดจำนวนคำถามหรือยอดใช้รวม**

`docker compose exec app node ops/usage.mjs 7` แสดงจำนวนครั้งและโทเคนที่ Hermes รายงานย้อนหลัง 7 วัน โดยไม่เก็บข้อความผู้เรียนเพิ่มเติม ตัวเลขอาจไม่รวมการลองซ้ำภายใน Hermes หรือคำขอที่ล้มก่อนส่ง usage จึงใช้เพื่อดูแนวโน้มเท่านั้น ยอดเงินและเพดานค่าใช้จ่ายจริงต้องดูและตั้งที่ผู้ให้บริการ AI ที่ผู้ติดตั้งเลือก

## คำสั่งประเมิน

```sh
npm test
npm run evaluate
TUTOR_URL=https://<เว็บทดสอบของคุณ> npm run evaluate:live
TUTOR_URL=https://<เว็บทดสอบของคุณ> npm run evaluate:live -- --code
```

ตัวประเมินผ่านเว็บจะส่ง 12 คำถามจริง ซึ่งอาจใช้เครดิต AI แล้วลบแชททดสอบหลังแต่ละข้อ ผล `PASS` ยืนยันเพียงการตอบและอ้างอิงบทที่คาดไว้ ต้องอ่านคำตอบด้วยคนอีกชั้นหนึ่ง โหมด `--code` ส่งอีกสองคำถามและต้องมี `clang` เพื่อเช็กไวยากรณ์โค้ด C
