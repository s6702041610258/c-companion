# ผลตรวจ C Companion รุ่น rc.2 ก่อนแก้ — 26 กันยายน 2026

เอกสารนี้เก็บหลักฐานของปัญหาที่พบใน `0.3.1-rc.2` เพื่อเทียบก่อนและหลังแก้ คะแนน 73/100 ด้านล่างเป็น **คะแนนก่อนแก้** ไม่ใช่คะแนนของ `0.3.1-rc.3` ดูผลยืนยันรุ่นล่าสุดใน [RELEASE-GATE-TH.md](RELEASE-GATE-TH.md)

## คำตัดสิน

**ความพร้อมต่อเป้าหมายรุ่น 1.0 สำหรับแจกให้ผู้อื่นติดตั้ง: 73/100 (ประมาณ 73%, ระดับ C)** เป็นคะแนนความมั่นใจทางวิศวกรรม ไม่ใช่อัตราคำตอบถูกทุกคำถาม หลักฐานครอบคลุมประมาณ 90% ของหัวข้อประเมิน ความเชื่อมั่นระดับปานกลาง เพราะยังไม่มีการติดตั้งจริงบน Windows/Linux และยังพบการค้นหน้าหนังสือพลาด รุ่นปัจจุบัน **พร้อมให้เพื่อนทดลอง** แต่ยังไม่ควรเรียกว่ารุ่นสมบูรณ์

ขอบเขตการตรวจคือชุด `0.3.1-rc.2` ที่ติดตั้งบน macOS ARM ด้วย Hermes และผู้ให้บริการ AI ที่เจ้าของเลือก ไม่ได้ตรวจ VPS สาธารณะหรือเครื่องของเพื่อน ไม่มีการเปลี่ยนโค้ดหรือข้อมูลผู้ใช้ในการตรวจนี้

## หลักฐานที่ทำจริง

- เปิด Docker Desktop และเปิดบริการ `hermes`, `app`, `backup`, `monitor` ในชุดติดตั้งเดิม ทุกบริการรันอยู่; `/api/health` รายงาน `ok: true`, รุ่น `0.3.1-rc.2`, หนังสือ 107 หน้า
- ถามผ่านหน้าเว็บจริง 1 ข้อเรื่องตัวแปรที่ยังไม่กำหนดค่า: ตอบถูกและแสดงแหล่งอ้างอิง หน้าเว็บยังเก็บคำถามนี้ไว้ให้เจ้าของตรวจ
- ส่งคำถามท้าทายผ่าน API 26 ครั้ง: ตอบสำเร็จ 24 ครั้ง และตอบ HTTP 502 สองครั้งในคำถามเดียวกันเรื่องหลักฐาน `%9s`; บทสนทนาของ 26 ครั้งนี้ลบหลังตรวจทุกครั้ง
- ถามซ้ำโดยเลือกบทอาร์เรย์โดยตรง 1 ครั้ง: ตอบค่าที่เหลือเป็นศูนย์พร้อมอ้างหน้า 51 ได้ถูกต้อง
- ทดสอบโหมดติวทีละขั้นและฝึกทำโจทย์อย่างละ 1 ครั้ง: ตอบตามรูปแบบและอ้างหน้าในบทที่เลือกได้
- โค้ดที่บอตสร้างสำหรับเลขคู่/คี่และตัดเกรดผ่าน `clang -std=c11 -Wall -Wextra -Werror`; ทดลองค่าเลขคู่/คี่ 3 ค่าและคะแนนขอบ 12 ค่า ผ่าน 15/15
- การตรวจรุ่นก่อนหน้าในงานเดียวกัน: unit test 51/51, retrieval 18/18, live evaluation 18/18 และการคืนข้อมูลจากสำเนา ผ่านแล้ว; ไม่ได้รันซ้ำเพราะไม่มีการแก้โค้ดหลังการตรวจนั้น

## คำถามที่ตอบไม่ได้หรือไม่ครบ ทั้งที่หนังสือมีหลักฐาน

| คำถามที่ลอง | ผลจริง | หลักฐานในหนังสือ | สาเหตุที่ตรวจพบ |
|---|---|---|---|
| `int a[5] = {75, 25}; ค่า a[4] เป็นเท่าไร` | บอกว่าไม่มีเนื้อหาเรื่องสมาชิกที่ไม่ระบุค่า | หน้า 51 ระบุ `{75, 25, 0, 0, 0}` ชัดเจน | การค้นทุกบทเลือกหน้าอื่นที่มี `int` บ่อย หน้า 51 ไม่ติด 4 หน้าแรก |
| ถามเรื่องเดียวกันโดยเติมคำว่า “อาร์เรย์” | ยังบอกว่าไม่มีเนื้อหา | หน้า 51 | หน้า 61, 50, 82, 53 ได้คะแนนค้นสูงกว่า; เมื่อจำกัดบท 6 จึงตอบถูกและอ้างหน้า 51 |
| `sizeof(int) เท่ากับ 4 ไบต์ทุกเครื่องใช่ไหม` | ตอบว่าไม่พบเนื้อหาเกี่ยวกับ `sizeof(int)` และไม่ตอบประเด็นหลัก | ตารางหน้า 15 ระบุ `int` เป็น 4 ไบต์ในหนังสือ แต่ห้ามตีความเป็นค่าคงที่ทุกเครื่อง | คำว่า `int` ทำให้หน้าที่กล่าวซ้ำบ่อยแซงตาราง; ควรแยกตัวเลขตามหนังสือกับข้อเท็จจริงเรื่องความพกพา |
| `หนังสือหน้า 15 เขียนว่า long long ขนาด 4 bytes ใช้ได้กับทุกเครื่องไหม` | สองครั้งบอกว่าได้รับเพียงหน้า 14 ทั้งที่หนังสือมีหน้า 15 | ตารางหน้า 15 ระบุขนาดดังกล่าว | คำว่า “เขียน” ไปกระตุ้นตัวจำแนกโจทย์เขียนโปรแกรมและแทนชุดหน้าอ้างอิง; เมื่อเปลี่ยนเป็น “ตาราง...ระบุ” จึงตอบถูกและอ้างหน้า 15 |

## คำตอบถูกแต่หลักฐานหรือความทนทานยังมีปัญหา

| กรณี | ผลตรวจ | ความเสี่ยง |
|---|---|---|
| `a[3]` ของอาร์เรย์ขนาด 3 | ตอบถูกว่าเกินขอบเขต แต่ชี้หน้า 61 เรื่อง pointer index แทนหน้า 51 เรื่องช่วงดัชนีอาร์เรย์ | ผู้อ่านเปิดหน้าอ้างอิงแล้วไม่พบหลักฐานตรงคำตอบ |
| ค่าที่ `scanf` คืน | ตอบหลัก C ถูกแต่ชี้หน้า 26 ซึ่งสอนการรับค่า ไม่ได้อธิบายค่าคืน; เมื่อถามตรงว่า “หนังสือหน้าไหน” บอตยอมรับว่าไม่มีหน้าอ้าง | ต้องแยกความรู้เพิ่มเติมของผู้สอนออกจากข้อความที่หนังสือรองรับ |
| `%9s` กับ `char name[10]` | คำตอบด้านความปลอดภัยถูก แต่หน้า 26–27 ไม่ได้สอน `%9s`; เมื่อถามหา “หนังสือหน้าไหนสอน” ได้ HTTP 502 สองครั้ง | โมเดลส่งรูปแบบคำตอบไม่ผ่านการตรวจ (`invalid_model_format`) แล้วไม่มีการลองซ้ำที่ควบคุมได้ |
| `malloc/free` และ `static local variable` | ไม่อ้างว่าหนังสือสอนสิ่งที่ไม่มี ถือว่าคุมขอบเขตได้ | ข้อความ `malloc/free` กล่าวเหมือนหนังสือมี “เฉพาะหน้า 2” ทั้งที่จริงคือหน้าที่ระบบค้นส่งให้โมเดล ควรเขียนให้ชัดว่า “หน้าที่ค้นได้” |

คำถามอื่นในรอบนี้ เช่น pointer สะกดแปร, pointer ไม่กำหนดค่า, เลขคี่ติดลบ, `void`, `fopen`, `switch`, pass by value, datatype กับ `_Bool`, โจทย์ตัดเกรดและเลขคู่คี่ ได้คำตอบที่ไม่พบข้อผิดหลักในตัวอย่างที่ตรวจ การไม่พบข้อผิด **ไม่รับประกัน** ทุกคำถามหรือทุกโมเดล

## งานที่ควรทำตามลำดับ

1. **แก้การเลือกหน้าหลักฐาน**: จับสัญญาณ `a[5]`, หมายเลขหน้า, ชื่อบท และคำไทย–อังกฤษให้ดีกว่าการนับคำซ้ำ; แยก “หนังสือเขียนว่า” ออกจาก “เขียนโปรแกรม” เกณฑ์ผ่านคือคำถามอาร์เรย์และขนาดชนิดข้อมูลด้านบนตอบตรงพร้อมหน้า 51/15 เมื่อเลือก “ทุกบท” โดยคำถามเดิม 18 กรณียังผ่าน
2. **ตรวจความตรงของคำอ้างและรูปแบบคำตอบ**: อ้างเฉพาะข้อความที่หน้าหนังสือรองรับ จัดข้อความความรู้เพิ่มเติมเป็นหมายเหตุแยก; เมื่อ JSON โมเดลผิดรูปแบบ ให้ลองซ้ำแบบจำกัดและแสดงทางแก้ที่ชัด เกณฑ์ผ่านคือคำถาม `%9s` ซ้ำ 10 ครั้งไม่มี 502 และไม่อ้างว่าหนังสือสอน `%9s` หากไม่มีหลักฐาน
3. **ประตูรุ่นเต็ม**: ติดตั้งจาก ZIP บน Windows จริง และ Linux หากจะประกาศรองรับ; ตรวจการเชื่อมผู้ให้บริการ AI ของผู้ติดตั้ง การเปิดซ้ำ การคืนข้อมูล และอัปเกรด/ย้อนรุ่น ก่อนเปลี่ยนป้ายจากรุ่นทดลองเป็น 1.0

## เรื่อง “ให้ Hermes เรียนรู้จากคำถามผู้ใช้” — วิเคราะห์เท่านั้น

Hermes มีความจำข้ามบทสนทนา แต่ความจำไม่ใช่การฝึกน้ำหนักโมเดล และชุดติวเตอร์นี้ปิดความจำของ Hermes ฝั่ง API เพื่อไม่ให้ข้อมูลผู้ใช้หนึ่งคนไปรบกวนคนอื่น แนวทางที่เหมาะคือเก็บคำถามที่ค้นไม่เจอเป็น **รายการตรวจ** โดยไม่ถือข้อความผู้ใช้เป็นความจริง จัดกลุ่มคำถาม ตรวจหน้าในหนังสือหรือเนื้อหาเพิ่มเติมที่ผู้สอนอนุมัติ แล้วออกชุดความรู้ที่มีเลขรุ่น แหล่งที่มาและการทดสอบย้อนหลัง ให้ลบข้อมูลส่วนตัวก่อนนำคำถามมาทบทวน ห้ามเพิ่มเนื้อหาอัตโนมัติจากคำถามอย่างเดียว เพราะอาจรับข้อเท็จจริงผิดหรือคำสั่งแฝงเข้าไป
